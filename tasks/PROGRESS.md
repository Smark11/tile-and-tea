## M0.1b Screenshot harness
- `npm run screenshots` (`scripts/screenshots.mjs`) starts `expo start --web` on port 8099 (override with `SCREENSHOT_PORT`; it refuses a busy port), waits for Metro's `/status`, then uses Playwright Chromium to capture each route at 393×852 @3x (1179×2556, the real iPhone 15) in light and dark mode into `app/screenshots/<route>-<scheme>.png`. It clears old PNGs first and stops the dev server's process group afterward.
- Routes are found automatically from `src/app/` (`scripts/routes.js`, unit-tested in `scripts/__tests__/`). It skips layouts, `+` files, API routes, native-only variants, and dynamic `[param]` routes. Groups are stripped. Set `SCREENSHOT_ROUTES=/,/dev/styleguide` to capture a subset. Dynamic routes need a future harness option if we want them.
- Page JS errors and console errors make the run exit 1, so a broken screen can't pass silently. There's a 1s settle delay for entrance springs.
- One-time setup on a new machine: `npx playwright install chromium` (the script prints this hint if the browser is missing). Playwright is a devDependency.

It parses to `HandGroup`s, prints a `CardLine` (x is printed as 1), and builds the spoken line. `variants.ts` has `handVariants` (every concrete suit/number choice, deduped by tile key) and `jokersNeeded`/`isBuildable` (Jokers only in groups of 3+, at most 8). **M2.2/M2.3 should build on `handVariants`.** `SUIT_DRAGON` now lives in `tiles.ts`.
- `practice-card-2027.ts` has 40 original hands, 4 in each of 10 categories, written from scratch. `CURRENT_CARD` (in `index.ts`) parses it at load, and a bad notation throws. Tests prove: every variant is 14 tiles and buildable from one set; no two hands share a variant; hands with no group of 3+ are concealed; concealed hands pay more (50) than exposed ones (25–45); each category keeps its promise (year digits only, evens/odds/369, like numbers, unbroken runs, quints, no numbers in Winds & Dragons, addition notes are true sums spelled in tile order).
- Rules interpretations (standard American): Jokers may fill Flower groups of 3+. Hands with singles (2027, NEWS, 2468, 13579) can still be X, because only their pungs/kongs get exposed.
- `CardLine` types moved to `game/card/types.ts` (lessons re-exports them). `CardLineView` now exports `CardLineBody` and `SuitMark`. New `/card` route (`components/card/PracticeCardScreen.tsx`) prints the whole card on one ivory sheet with a masthead, a suit/X/C key, and gold ornaments between sections. Each hand row is one a11y element ("Quints, hand 2 of 4. …"). The Learn tab ends with a `PracticeCardLink` peek card. The siteMeta `/card` entry is noindex. There's no new analytics event; screen tracking covers the page view.
- Design review fixes: `CardLineBody` lays out groups with `balanceRows` (exported, unit-tested). It measures each group with onLayout and uses the fewest rows whose lengths differ by at most one (7 → 4+3, 3+2+2), so a line never leaves one group orphaned on its own row. Lines with 6+ groups print denser (18pt glyphs, 6pt gap), so `NN EE WW SS 11 22 33` fits one row on a 390pt phone. The card's key text and section blurbs are now 17pt. The key is two intentional lines. Back is centered on the title line.

## M2.2 Hand matcher
- `src/game/card/matcher.ts` (exported from `game/card`): `findMahJongg(declaration, card)` returns every hand the 14 tiles complete, highest value first with card order breaking ties; `matchHand(hand, declaration)` checks one hand; `declarationProblem` flags impossible input (not 14 tiles, too many copies, an exposure smaller than a pung, mixed, or all Jokers), and the matchers then return no match. A `Declaration` is `{ concealed: TileKind[], exposures?: TileKind[][] }`, with the winning tile counted in `concealed`. Each `HandMatch` gives the variant (suit/number choices), every unit's real-tile and Joker counts in printed order, which exposure filled it, and the total Jokers. M2.4 scoring can build on that (e.g. jokerless).
- Rules (standard American): Jokers only fill groups of 3+. Each exposure must be exactly one pung/kong/quint of the hand, the same tile and size (a pung can't stand for a kong; three singles like 2027's Soaps can't be exposed). A concealed hand loses if anything was exposed, but it can still be won on a discard because that tile counts as concealed. Jokers can leave several hands complete (333 666 + 8 Jokers → threes-4, threes-2, runs-1), so callers should score the first match.
- The algorithm: per variant, exposures greedily claim identical units; then a per-tile bound check (strict real tiles for singles/pairs ≤ held ≤ strict + flexible). Variants are cached per `Hand` in a WeakMap. A whole-card check is well under 16 ms. Tests compare it against an independent bipartite-matching referee on about 2.5k seeded fuzz declarations, plus every variant, every Joker pattern, every exposure subset, and near misses.

## M2.3 Hand distance
- `src/game/card/distance.ts` (exported from `game/card`): `handDistance(hand, holding)` and `cardDistances(holding, card)`. A `Holding` is the `Declaration` shape with up to 14 tiles. `tilesAway = 14 − exposed tiles − the most rack tiles the hand can use`, so 13 tiles one short is 1 away, and 0 means Mah Jongg (a fuzz test checks it agrees with `matchHand`). Results are closest first, with card order breaking ties, then the unreachable hands (`tilesAway: null`, `reason`: `concealed-hand` | `exposures-dont-fit` | `tiles-gone`). Each reachable hand gives its closest variant (ties go to fewer Jokers needed), a per-unit plan (`naturals`/`jokers`/`missing`/`exposure`) and `mustBeJokers`, the missing tiles that can only be Jokers because the player already holds every real copy. **M3.2/M3.4 explanations should build on the plan.** Bad input throws a RangeError; the new `holdingProblem` in matcher.ts gives the reason.
- Rules (standard American): real tiles go into singles and pairs first, and Jokers only fill groups of 3+. Exposures are fixed, as in the matcher. Copies on the player's own rack and exposures count as gone, so a pair whose last copies are in the player's exposures is out of reach. Tiles other players have discarded or exposed are **not** considered yet; the M3.4 dead-tile logic should add that.
- Speed: variants are compiled once per hand to tile indexes (`variantsOf` moved to variants.ts so the matcher and distance share one cache). The benchmark test requires a median under 2 ms and a p95 under 4 ms per whole-card ranking on a dev machine, leaving room for a phone several times slower within 16 ms. An independent referee (bipartite matching plus a fill check) agrees on 400 fuzzed holdings × 40 hands. Completing each plan always gives a valid Mah Jongg with exactly `mustBeJokers` Jokers drawn, and one draw never moves a distance by more than 1.

## M2.4 Game state machine
- `src/game/engine/` (pure TS, plain JSON state for M4.4 save/resume): `newGame(seed)`, `step(state, action, card?)` → `{ok, state} | {ok:false, error}` (never mutates), `gameReducer` for `useReducer` (illegal actions are ignored), and `awaiting(state)`, the seats the game is waiting on (bots and the M4 table UI should drive off it). Actions take tile **ids**. Seats are 0 E, 1 S, 2 W, 3 N, in turn order; `rightOf` is next to play. A call window (`calls` phase) closes when every live non-discarder answers, or on `closeCalls` (the M4.3 timer).
- Rules chosen (standard American): East discards first without drawing, and Mah Jongg on the dealt 14 counts as self-drawn. Blind passes on first-left/second-right forward the *incoming* tiles of that pass, so tiles can chain past several blind passers (`resolvePass`, FIFO, so it's deterministic). Courtesy uses the smaller offer across. A discarded Joker can't be called, even for Mah Jongg. Calls are 3–6 tiles. Mah Jongg beats an exposure, otherwise the caller next in turn wins. Joker swaps are allowed on your own turn after drawing or calling, from any exposure (dead hands' included). Settlement: discarder ×2, others ×1; self-drawn all ×2; jokerless doubles again, except hands with no 3+ group (`allowsJokers`: Singles & Pairs and year-4), and the winner gets the best-paying matching hand. An invalid Mah Jongg declaration or call is *refused* (`not-mah-jongg`), not punished, since the UI should prevent it.
- Dead hand = the player's exposures fit no card hand (checked automatically after each exposure, using `cardDistances` with exposures only). They discard to finish that turn, then sit out (turns skipped, no calls, swaps or wins) but still pay. **For the checkpoint, confirm with a real player:** (1) dead hands sit out (current NMJL practice, as I understand it) rather than keep drawing and discarding; (2) when three hands are dead the game ends with no payment (`result.type: 'deadHands'`); (3) whether East's dealt Mah Jongg counts as self-drawn. Dead hands from tiles visible elsewhere, and challenges by other players, aren't modelled.
- Tests: `engine/__tests__/` (charleston, play, scoring, and fuzz: 24 seeded random games of legal play with conservation/size/dead-hand invariants checked after every action, on deep-frozen states). The table builder in `engine/__fixtures__/table.ts` pads racks with filler (it sits outside `__tests__` so Jest doesn't run it as a suite).

## M3.2 Best Hand drill
- `drills/content/bestHand.ts` (`best-hand`, skill `hand-choice`): a 13-tile rack, sorted and grouped by suit on the felt, and four card lines to choose from. Fully random racks were 7–9 tiles from everything with many ties, so the rack is dealt "post-Charleston": 5–8 tiles from one random hand, the rest from the wall. **The answer never comes from the deal.** `cardDistances` must find exactly one closest hand on the whole card (2–6 tiles away), and the deal is redone until it does. The other choices are the runner-up (one tile further, when one exists) plus hands up to 5 further, from sections not already shown. Verdicts: closest = best (1), one tile further = good (0.5), further still = miss.

## M3.3 Charleston drill
- `drills/content/charleston.ts` (`charleston`, skill `charleston`) deals a 13-tile rack: 5–7 tiles lean toward one random hand, the rest come from the wall, and the closest hand is 4–6 tiles away. The player picks 3 tiles to pass right, then taps Check. Jokers are `locked` choices (a new optional `DrillChoice.locked` reason), and the round reducer ignores taps on them. `analyzeRack` judges every distinct pass by the 10 tiles it keeps: (1) the closest hand after the pass, and (2) backups, meaning other hands within one tile of it. Best = optimal on both counts, good = keeps the closest hand but loses a backup, miss = moves the closest hand further away. It only watches hands within one tile of the best pass's closest, widening lazily. That shortcut is exact (an independent whole-card referee in the tests agrees on every pass), and a question takes about 15–20 ms to generate.
- The generator only asks fair racks: at most 25% of passes are best, at least 35% are misses, the best pass keeps the closest hand where it was, and at least one best pass doesn't split a dealt pung. The highlighted answer is a best pass that keeps pungs whole; ties go to the pass closest to the player's pick, then to the one splitting the fewest pairs. A miss's explanation names the tiles it cost using `tilesItNeeds` (the smallest sub-pass that costs as much as the whole pass). When the hand could spare some of those tiles but not all, it says "it needs two of your A, B and C". Distances are spelled out ("six tiles away") so they don't run into labels like "hand 3".
- Framework additions: `DrillQuestion.choiceGroups` (suit groups for tile choices); `DrillEvaluation.target` (a card line shown as "Aim for · …" above the feedback); `accessibilityHint` on `Tile`/`SpreadTile`; a note on the felt explaining locked tiles; and, after an answer, the key "Raised: your pick. Starred: the coach's." `rackGroups` is now exported from bestHand, and `list()` takes an `'or'` joiner. The screenshot harness now captures up to 26 styleguide frames, because the new "Charleston drill" section sits near the end.
- Rules and coaching: the first Charleston's pass right is exactly 3 tiles, and Jokers are never passed. The advisor doesn't yet consider which tiles are dangerous to hand an opponent, or what comes back in later passes (including blind passes). M3.4's danger logic could feed into a later version.

Listed routes load with a fixed `?seed=`, and after the unanswered frames the script taps the picks, taps Check, scrolls back to the top and captures the result as the next frames (`drill-charleston-*-2.png` and `-3.png`, on phone and desktop, in light and dark).
